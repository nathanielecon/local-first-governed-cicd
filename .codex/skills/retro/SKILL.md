# Retrospect the Delivery

1. Read the release manifest, change record, pipeline reports, incidents, and review findings.
2. Compare expected and actual lead time, validation stage, manual steps, failures, and recovery time.
3. Separate root causes from symptoms and identify which earlier gate should have caught each problem.
4. Record actions with owner, acceptance criterion, and target phase in `docs/retrospectives/`.
5. Route proposed plan changes back through `spec` and `plan-eng-review`; do not edit authoritative state or discard failed evidence.
